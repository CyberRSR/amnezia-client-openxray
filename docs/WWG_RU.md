# WWG на Android

WWG — Android-цепочка из двух туннелей AmneziaWG. Оба слоя должны использовать одно поколение: v2/v2 или v3/v3.

```text
Android-приложение -> входной AWG netstack -> локальный UDP relay -> выходной AWG -> интернет
```

Входной туннель работает в официальном Go netstack AmneziaWG и открывает UDP relay на loopback. Только выходной слой создаёт системный интерфейс Android `VpnService`. Сокеты входного слоя защищаются вызовом `VpnService.protect`, поэтому они не могут зациклиться через выходной VPN.

DNS проходит по той же цепочке, что и обычный трафик: запрос входит в выходной туннель и затем переносится через входной. IPv4-only профиль не объявляет маршрут IPv6 по умолчанию, что исключает обход VPN по IPv6.

## Профили v2 и v3

Сначала импортируется входной `.conf` AmneziaWG, затем выходной. Старые профили v2/v2 продолжают работать без преобразования. Режим v3/v3 определяется по полям AWG3, включая `HeaderProtectionKey`; базовое поле `protocol_version` по спецификации AmneziaWG остаётся равным `2`.

WWG отклоняет смешанные цепочки v2/v3, неполные параметры AWG, повреждённые диапазоны AWG3, значения `S1..S4` меньше 8 в v3 и несовпадение `HeaderProtectionKey` клиента и сервера. Пустые `I1..I5` считаются отсутствующими.

Схема сохранённого контейнера:

```text
containers[].container = "amnezia-wwg"
containers[].wwg.underlay_awg = AwgProtocolConfig
containers[].wwg.overlay_awg  = AwgProtocolConfig
containers[].wwg.provisioning = необязательная capability создания peer
```

Android runtime получает:

```text
runtime.protocol = "WWG"
runtime.awg_underlay_config_data = <клиентский конфиг входного слоя>
runtime.awg_overlay_config_data  = <клиентский конфиг выходного слоя>
```

## Безопасный экспорт в файл и QR

Одна пара ключей и адрес WireGuard не должны одновременно использоваться на двух устройствах. Управляемый WWG-профиль типа **Master** предлагает два вида экспорта. Оба обращаются к входному и выходному provisioner по HTTPS с закреплённым сертификатом и транзакционно создают:

- новую пару приватного/публичного ключей X25519 для каждого слоя;
- новый PSK для каждого слоя;
- новый уникальный адрес `/32` и серверный peer для каждого слоя.

**Создать WWG-профиль только для устройства** удаляет provisioning-capability из созданного файла/QR. Получатель подключается со своими уникальными peer, но не может создавать или передавать новые профили. **Создать Master WWG-профиль** сохраняет capability, поэтому получатель может создавать следующие Master-профили и профили только для устройства.

Профиль-донор не изменяется. Файл и QR, показанные в рамках одной операции, содержат один и тот же новый профиль получателя; каждый следующий запуск экспорта создаёт новую пару peer на существующих серверных портах. Общесерверные параметры обфускации AWG, включая HPK/J/S/H, намеренно сохраняются: они не являются идентификатором устройства.

Импортированный старый профиль или профиль только для устройства без provisioning-capability продолжает подключаться, но действия делегирования для него не показываются. Ротация capability на сервере сразу лишает старые Master-профили возможности делегирования, не удаляя их существующие peer и не ломая туннели; попытка экспорта со старой capability отклоняется.

Если peer входного слоя создан, а создание выходного завершилось ошибкой, новый входной peer откатывается. Серверный API ограничен только операциями peer, имеет rate limit и короткоживущие rollback receipts и не умеет выполнять произвольные команды.

## Жизненный цикл и восстановление

Mutex и счётчик generation сериализуют всю цепочку. Перезапуск закрывает `overlay -> relay -> underlay`, затем запускает `underlay -> relay -> overlay`; второй worker или relay параллельно запустить нельзя.

Проверка здоровья выполняется каждые пять секунд. Частичный отказ одного endpoint записывается в лог, но не разрывает работоспособный VPN. Два полностью неуспешных раунда VPN-bound probe запускают только один restart текущей generation. Задержки повторов используют ограниченный backoff `5/15/30/60/120` секунд с jitter и сбрасываются после двух минут стабильной работы. Ручное отключение ждёт завершения monitor перед закрытием handles.

## Безопасность

Созданный `.vpn` или QR всегда содержит приватные данные подключения. Master-экспорт дополнительно содержит ограниченную capability для будущих уникальных экспортов, а экспорт только для устройства намеренно её не содержит. Оба варианта являются секретом: передавайте их только конкретному получателю. Provisioning работает по HTTPS с точным SHA-256 pin сертификата, а bearer-токены на сервере хранятся только как хеши.

Исходники, APK и публичные релизы не должны содержать рабочие профили, токены, приватные ключи, PSK, SSH-данные и адреса развёртывания. Серверные конфигурационные файлы следует хранить с правами `0600`.
